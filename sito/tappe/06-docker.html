Docker

Fin qui abbiamo acceso a mano tre programmi diversi: uno scritto in JavaScript, uno in C, uno che è un database. Ognuno ha la sua versione, le sue cartelle e le sue porte. Docker è il modo di accenderli tutti con un comando e di ritrovarli identici domani.

Quattro domande, nell'ordine in cui vengono in mente.

Domanda 1 · che cos'è un container?

Un programma impacchettato con tutto quello che gli serve per girare

Installare Node-RED sul proprio computer vuol dire installare anche una certa versione di Node.js, certe librerie, certe cartelle di configurazione. Sul computer del collega quelle cose sono diverse, e il programma si comporta diversamente.

Un'immagine risolve la cosa alla radice: contiene il programma e il suo contorno. Chi la scarica ottiene esattamente quello che aveva chi l'ha costruita. Un container è un'immagine che sta girando.

Condivide il nucleo del sistema che lo ospita

Una macchina virtuale porta con sé un sistema operativo intero e si misura in gigabyte. Un container condivide il nucleo del sistema che lo ospita e si misura in decine di megabyte. Per questo tre container si accendono in pochi secondi.

Domanda 2 · cosa gira, in questo progetto?

Tre servizi, ognuno con il suo mestiere e la sua porta

I tre servizi sono descritti in un file solo, edge/docker-compose.yml. Ogni voce dice quale immagine usare, quali porte aprire e quali cartelle condividere con il computer che li ospita.

Domanda 3 · cosa c'è scritto dentro?

Immagini con la versione fissata, porte, e cartelle condivise

edge/docker-compose.yml · servizio mosquitto, accorciato

  mosquitto:    image: eclipse-mosquitto:2    container_name: plcsim-mosquitto    restart: unless-stopped    ports:      - "1883:1883"    volumes:      - ./mosquitto/config/mosquitto.conf:/mosquitto/config/mosquitto.conf:ro      - ./mosquitto/data:/mosquitto/data      - ./mosquitto/log:/mosquitto/log

Clicca per accendere la riga

Node-RED è l'unico servizio costruito qui invece che scaricato pronto, perché ha bisogno della palette che parla OPC UA. Il file che lo costruisce è di due righe.

# edge/Dockerfile
FROM nodered/node-red:4.0.9
RUN npm install node-red-contrib-opcua@0.2.354 --no-audit --no-fund

Anche qui le versioni sono fissate. La palette installata a mano dall'interfaccia sparirebbe alla prima ricreazione del container, e il flow smetterebbe di funzionare senza spiegazioni.

Domanda 4 · come si accende e cosa resta dopo?

Un comando per accendere, e i dati restano sul disco

$ cd edge && docker compose up -d
Creating plcsim-nodered … done
Creating plcsim-mosquitto … done
Creating plcsim-postgres … done

$ docker compose down
i tre container spariscono, le cartelle condivise no

Lo storico di Postgres vive in edge/postgres/data, sul computer, non dentro il container. Spegnere e riaccendere non perde niente. Cancellare quella cartella sì, ed è l'unica maniera per farlo.

Postgres dichiara anche come si capisce che è pronto: Docker gli chiede pg_isready ogni cinque secondi finché non risponde. Serve perché un database acceso da due secondi accetta connessioni ma non è ancora in grado di lavorare.

Password in chiaro dentro il file

Utente, password e nome del database sono scritti in chiaro nel file, e il broker accetta chiunque. È dichiarato come banco di prova su una macchina sola, con l'irrobustimento previsto come tappa a sé.
